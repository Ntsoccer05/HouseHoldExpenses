## 2. サーバーレス移行後の試算

設計書（`serverless-migration-design.md`）の構成（Bref Lambda + 既存CloudFront/S3/RDS）を前提に、リソースごとに増減を積み上げる。

| 項目 | 現状 | 移行後 | 増減理由 |
|---|---|---|---|
| ECS (Fargate) | $7.81 | **$0** | ECS自体を廃止 |
| ALB | $17.56 | **$0** | Lambda Function URLは時間課金なし。ALBの固定費(時間課金+LCU)が丸ごと消える |
| VPC (Public IPv4) | $9.64 | **$0〜$3.65** | ECSタスク1個+ALB(2AZ)分=計3個のPublic IPv4アドレス課金(2024年以降 $0.005/h/個)が消える。LambdaのVPC ENIはPublic IPを持たないため課金対象外。ただしNAT用に新たに1個必要になる場合がある(下記) |
| RDS | $15.04 | **$15.04** | 変更なし（設計書3章の通り） |
| Route53 | $0.51 | **$0.51** | 変更なし |
| ECR | $1.36 | **$0** | BrefはS3経由のzipデプロイを採用するためコンテナイメージ不要（ECRリポジトリ自体は移行完了後に削除） |
| Lambda実行料金 | — | **$0〜$1** | 家計簿アプリの想定トラフィックでは無料枠（400,000 GB秒/月、恒久無料）内に収まる見込み |
| **NAT（新規）** | — | **要検討** | 下記3章参照。**ここが月額の分岐点** |

### 2.1 なぜNATが必要になるのか

LambdaをRDS（プライベートサブネット内）に到達させるにはLambdaをVPCにアタッチする必要がある。しかしVPCにアタッチされたLambdaのENIは**Public IPを持たない**ため、Google OAuthのトークン交換やメール送信(SMTP)など**外向きのインターネット通信ができなくなる**（現状のECSはパブリックサブネット+Public IP自動割当で直接インターネットに出られているため、この制約が表面化していなかった）。

対策は2択：

| 方式 | 月額目安 | 特徴 |
|---|---|---|
| **NAT Gateway（AWS管理）** | 約 $45〜50 | 運用不要・信頼性高い。ただし固定時間課金が大きく、このアプリの規模では**移行のメリットを打ち消してしまう** |
| **NATインスタンス（自前, t4g.nano）** | 約 $6〜7 | 低コスト。姉妹プロジェクト（TrainingMemoApp）でも採用実績あり。ただし`serverless-migration-lessons-learned.md`(3-10)記載の落とし穴（iptablesのインターフェース名ハードコード、Docker同梱AMIのFORWARD DROPポリシー等）を踏まえた実装が必須 |

## 3. 結論：月額いくら安くなるか

### シナリオA: NATインスタンス採用（推奨・コスト最優先）

```
RDS                 $15.04
Route53              $0.51
Lambda実行料金        $0.50
NATインスタンス(EC2)   $3.07
NAT用 Public IPv4     $3.65
--------------------------------
小計                $22.77
Tax (約10%)          $2.28
--------------------------------
合計               $25.05 / 月  （約 ¥3,760 / 月）
```

**現状 $57.11 → 移行後 $25.05 ＝ 月額 約 $32.06（約 ¥4,800）削減、約 56% の削減**

### シナリオB: NAT Gateway採用（AWS管理・信頼性優先）

```
RDS                 $15.04
Route53              $0.51
Lambda実行料金        $0.50
NAT Gateway         $45.32
--------------------------------
小計                $61.37
Tax (約10%)          $6.14
--------------------------------
合計               $67.51 / 月  （約 ¥10,130 / 月）
```

**現状 $57.11 → 移行後 $67.51 ＝ 月額 約 $10.40（約 ¥1,560）の増加（コスト削減にならない）**

### 判断

- **コスト削減が目的なら NAT インスタンス一択**（シナリオA、約56%削減）。ただしlessons-learnedの既知の罠を踏まえた実装・検証が前提。
- 信頼性を優先してNAT Gatewayを選ぶ場合、**このアプリの規模ではサーバーレス化そのものが金銭的メリットを持たない**（可用性・運用性の向上が主目的になる）。
- 本リポジトリのTerraform（`infra/terraform/modules/network`）は`nat_type`変数で両方を切替可能にしてある。デフォルトは`instance`（シナリオA）。

## 4. 前提・注意事項

- Lambda実行料金は想定トラフィック（家計簿アプリ、少人数利用）を前提とした概算。実測後に`serverless-migration-lessons-learned.md` 3-19の手法（CloudWatch Logs Insightsでの実測）で検証すること。
- コールドスタート対策（EventBridge定期ping、`serverless-migration-lessons-learned.md` 3-20）を導入する場合、Lambda実行料金がやや増えるが無料枠の範囲内に収まる可能性が高い（TrainingMemoAppの実績ベース）。
- Tax（消費税）は現状の請求比率（総額の約9〜10%）から按分しており、正確な税率計算ではない。
- 上記は「移行後にECSを完全に削除した」場合の恒久コスト。移行期間中はECSとLambdaが並行稼働するため、その間は一時的にコストが増える。
- NATインスタンスの障害時、DB接続自体（RDSはVPC内直結）には影響しないが、OAuthログイン・メール送信など外向き通信のみが止まる。可用性要件次第ではNAT Gatewayや将来的なマルチAZ化を再検討する。
